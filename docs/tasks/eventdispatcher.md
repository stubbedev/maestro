# Task: internal/eventdispatcher and internal/script

Port .ref/composer/src/Composer/EventDispatcher (Event, EventDispatcher, EventSubscriberInterface, ScriptExecutionException) and .ref/composer/src/Composer/Script (Event, ScriptEvents), plus the event classes that live elsewhere but are plain data (Installer\PackageEvent/PackageEvents, Installer\InstallerEvent/InstallerEvents, Plugin\* events: PreFileDownloadEvent, PostFileDownloadEvent, PrePoolCreateEvent, CommandEvent, PreCommandRunEvent, PluginEvents) — define them here or in the package that owns their data, avoiding cycles; document where.

EventDispatcher must behave exactly as Composer's: listener priorities and ordering, script listeners from composer.json (`@other-script` references, `@composer`, `@php`, `@putenv`, `@additional_args`, Composer\\Config::disableProcessTimeout and other special callables, recursion detection with its exact message, COMPOSER_DEV_MODE / COMPOSER_BINARY / PATH (vendor/bin prepended, bin-dir) / COMPOSER_RUNTIME_ENV environment, the "> script" output lines with verbosity rules, exit-code → ScriptExecutionException messages, `stopPropagation`, `--no-scripts`, process timeout handling), and PHP-callable listeners (`Vendor\\Class::method`) and plugin listeners through the plugin runtime interface docs/PLUGINS.md specifies (the runtime itself is ported later; define the interface it implements, and make dispatch work for shell/@php/@composer scripts now). COMPOSER_BINARY points to the small PHP launcher described in docs/PLUGINS.md — record what the launcher needs and stub its path behind a function the composer package will provide.

Tests: port .ref/composer/tests/Composer/Test/EventDispatcher/EventDispatcherTest.php (every case; PHP-callable cases go through a fake plugin runtime implementing your interface) and Test/Script/*. Integration tests running real shell scripts and `@php -r` with the devenv php.

Scope: internal/eventdispatcher, internal/script. Use internal/pkg, internal/config, internal/util, internal/io.
Report: public API, where each event type lives, test counts, lint/test status.
