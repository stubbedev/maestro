# Task: internal/archive and internal/store

See PORTING.md deviations 1 and 2. The prototype's store is in git history (`git show 064b0d0:internal/store/store.go`, `manifest.go`, `place.go`, `clone_linux.go`, `clone_darwin.go`, `umask_unix.go`): read it for its lessons (atomic publish by rename, Composer's single-top-level-directory rule, refusing archives whose extraction isn't reproducible, reflink then copy, permission edge cases); the new design is different.

1. `internal/archive` — native extraction of zip, tar, tar.gz/tgz, tar.bz2, tar.xz (github.com/ulikunitz/xz), plain .gz, producing exactly what Composer's preferred extractor produces on Unix. For zip that is `unzip -qq <file> -d <dir>` (Info-ZIP UnZip 6.0; study unix/unix.c mapattr/close_outfile/set_direc_attribs/filtattr: modes from Unix external attributes with setuid/setgid/sticky stripped (no -K), no umask for entries with Unix attributes but umask for MS-DOS/FAT-made ones, read-only attribute mapping, directory modes applied at the end, symlinks from S_IFLNK entries created last, empty files, implied directories 0777&~umask, "../" and absolute path stripping as unzip does, backslashes in names, duplicates, exit codes as Composer treats them). For tars, what TarDownloader's PharData::extractTo produces (verify modes/links in practice). Then ArchiveDownloader's rule: a single top-level directory (ignoring .DS_Store) is the package root. Output is a stream of entries (path, kind, mode, link target, content reader) for the store, not files on disk. Safe against hostile archives (zip slip, symlink escapes, bombs: caps on total/per-entry size, entry count, ratio; duplicate names; NUL; invalid UTF-8 handled as unzip does or refused); unreproducible archives return a typed error the caller reports like Composer reports an extraction failure.
2. `internal/store` — per-file content-addressed store shared by all projects/worktrees. Under internal/cache.Dir() (you may extend internal/cache): `files/<2 hex>/<rest of sha256>[-<mode>]` keyed by content AND permission bits (so a hardlink always has the right mode), and an index per extracted release keyed by dist identity (reference / url / shasum + extraction-rules version) listing every entry (path, kind, mode, link target, content hash). Atomic writes (temp + rename), dedup across all packages/versions. Writable vendor: Composer leaves vendor files writable (0644) and tools like cweagans/composer-patches modify them; pnpm keeps normal modes and relies on rename-on-write. Decide, document in the package doc, and make in-place modification of a hardlinked file detectable (size/mtime in the index) so the store heals/re-verifies before reuse. Import into the install path by reflink (FICLONE / clonefile) → hardlink → copy, chosen once per destination device per run, overridable by MAESTRO_PACKAGE_IMPORT_METHOD=auto|clone|hardlink|copy. Dirs and symlinks created fresh; each package dir published atomically (sibling temp + rename). Parallel imports; two processes inserting the same content both succeed. Maintenance: Prune (last-used markers, N days), Verify, stats (bytes saved). Minimal syscalls: one open+write per new file, trust the index, batch mkdirs, reuse buffers.
3. API for the downloader port: "ensure this archive (or this dist with reference/shasum/url) is in the store, then materialize package X at path P", and "materialize from an existing index without the archive" — a warm second worktree touches neither the network nor the archive.

Tests: unit tests for every rule; a differential test over a large generated zip corpus (Go archive/zip with crafted external attributes, creator OS, symlinks, listed/implied dirs, modes 0600/0664/0775/0444/04755, empty dirs, .DS_Store, nested single dirs, unicode names) plus real package zips (a tools/ script fetches ~20 popular dists into a cache used when present; tests pass offline on the generated corpus), comparing extraction+store+import against real `unzip -qq` + the single-dir rule, entry by entry (type, mode, content, link target), under umask 022 and 002. Fuzz: no hostile archive writes outside the destination or imports content not matching its hash. Race tests for concurrent inserts/imports. Benchmarks: 3,000-file package import (clone/hardlink/copy), cold insert.

Scope: only internal/archive, internal/store, internal/cache, tools/ (fetch script), go.mod/go.sum via `go get`. Ironclad.
Report: design decisions (esp. writable vendor), public API, differential results, benchmarks, lint/test status.
