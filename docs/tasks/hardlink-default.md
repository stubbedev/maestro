# Task: hardlinks by default (pnpm `auto`), per the user's decision

The user chose pnpm semantics: maximum on-disk dedup on ext4, accepting that an in-place edit of a hardlinked vendor file is visible in other projects using that release until their next install. Commit 326d0c4 removed hardlinks (reflink else copy). Change it to:
- `MAESTRO_PACKAGE_IMPORT_METHOD=auto` (default) = reflink clone where the filesystem supports it, else hardlink, else copy — chosen per destination device once per run; explicit `clone`, `hardlink`, `copy` also accepted (explicit methods fail instead of falling back).
- Safeguard: packages of type `composer-plugin` are always imported by clone-or-copy (never hardlinked): plugin installers (phpstan/extension-installer, infection/extension-installer, ...) rewrite their own files in place, and hardlinking them would leak one project's generated config into others.
- Keep everything the store-heal task built: store objects only written via temp+rename by the store; tainted objects (stamp mismatch, incl. link-count/size/mtime as appropriate for hardlinked objects) are healed from the cached archive before reuse; never import a tainted object. Re-think the stamp check for objects that are legitimately hardlinked into vendor dirs (link count > 1 is now normal) — detect content changes reliably and cheaply (size + mtime + ctime/inode as available), document the exact guarantees and the accepted pnpm risk in internal/store's doc and PORTING.md deviation 1.
- BinaryInstaller's chmod must not change a hardlinked store object's mode: reintroduce unsharing (copy-then-rename) before chmod when the file is hardlinked (that is what store.Chmod did before — restore it, DRY).
- Tests: hardlink path on ext4/tmpfs (this machine), concurrency, the plugin-package safeguard, chmod unsharing, healing; the full e2e suites (MAESTRO_E2E=1 TestE2E, TestE2EPlugins) with the default method must pass cold and warm — phpstan/infection fixtures included.
- Also fix the clock-dependent `TestShowCommand_Show/outdated_deps_sorting_by_age` (internal/command): compute release age the way Composer does (PHP's default timezone semantics) and make the test independent of the time of day.

Scope: internal/store, internal/downloader, internal/installer (BinaryInstaller chmod), internal/command (show age), docs. A plugin phase-5 agent works concurrently in internal/plugin; coordinate via HANDOFF.md. Commit nothing.
