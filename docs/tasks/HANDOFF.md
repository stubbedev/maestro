# Hand-off notes between ports

Requirements finished ports place on later ones. Read the section for any
package you port.

## internal/downloader, internal/installer (from internal/store, internal/archive)
- Import method: `store.ParseMethod(os.Getenv(store.MethodEnv))`; the store never reads the environment itself.
- Verify the dist shasum as Composer's FileDownloader does; the store does not.
- Reproduce PharData's extension check: Composer fails tar dists whose URL path has no extension; `archive` doesn't check it.
- Create the parent of `dst` before `store.Materialize`.
- (hardlink-default) Package files may be hardlinks to store objects (pnpm's `auto`: reflink, else hardlink, else copy). Any in-place change maestro makes to a package file must unshare it first: chmod goes through `store.Chmod` (BinaryInstaller, FileDownloader), which unshares a hard-linked file (`store.Unshare`, copy then rename) before changing its mode. `store.Materialize`/`store.Install` take `store.ImportOptions`; `Unshared: true` (clone or copy, never hardlink) is what internal/downloader passes for composer-plugin/composer-installer packages.
- (store-heal) The archive downloaders read the store only on a files cache hit: `ErrNotFound`/`*MissingError` mean "extract the cached archive" (internal/downloader's doc).

## internal/autoload (from internal/classmap)
- Set `classmap.Parser.ShortOpenTag` from the user's real php configuration (php.ini usually turns it Off; the Go default is PHP's built-in On).
- Errors from the exclusion `Matcher` come back unwrapped; treat them like PHP's PcreException (a RuntimeException).

## internal/composer, internal/command, internal/installer, internal/plugin, internal/autoload, internal/downloader, internal/repository, internal/resolver (from internal/eventdispatcher)
- Every event type lives in internal/eventdispatcher (the dispatcher creates them, and all their dispatchers sit above it): `Event`/`BaseEvent`, `ScriptEvent` (Composer\Script\Event), `PackageEvent`, `InstallerEvent`, `CommandEvent`, `PreCommandRunEvent`, `PreFileDownloadEvent`, `PostFileDownloadEvent`, `PrePoolCreateEvent`, `PHPEvent` (PHP-owned), plus the PackageEvents/InstallerEvents/PluginEvents name constants. internal/script holds only the ScriptEvents constants (`script.PostInstallCmd`, ...), which the dispatcher imports.
- Resolver types are held loosely: an operation must implement `eventdispatcher.Operation` (`String()` = `__toString`); `Transaction` and PrePoolCreateEvent's request are `any`; repositories are `pkg.Repository`; PreFileDownloadEvent's downloader is an `http.Getter`.
- Factory: `eventdispatcher.New(composer, io, process)`, `SetRunScripts(!disableScripts)`, then `SetScriptRuntime(plugin runtime)`, `SetPHP(&eventdispatcher.PlatformPHP{View: ...})` with the process-wide `ComposerView` taken at startup (the default probes php itself), and `SetEnsureComposerBinary(fn)`.
- `composer.Composer` must implement `eventdispatcher.Composer`: `Package()`, `Config()`, and `ScriptAutoloader()` returning the current local repository's canonical packages, the generator's `SetDevMode`, and `CreateLoader(packages)` = buildPackageMap(im, root, packages) + parseAutoloads + createLoader(map, vendor-dir) (with createLoader's classmap warnings) as `*eventdispatcher.LoaderContents`. A PartialComposer implements only `Package()`/`Config()`.
- COMPOSER_BINARY: set it at startup, as bin/composer does (`Platform::putEnv('COMPOSER_BINARY', realpath(argv[0]))`), to the launcher's deterministic path `<shim dir>/bin/composer` without extracting anything; the `SetEnsureComposerBinary` hook extracts the shim before a script process starts. The launcher (docs/PLUGINS.md D13) is a PHP 7.2.5-compatible script run as `php -d allow_url_fopen=… -d disable_functions=… -d memory_limit=… <launcher> args…` (`@composer …`, `composer …` scripts, `PHP_BINARY $COMPOSER_BINARY` in plugins); it must run maestro with the same arguments (find maestro through an env var maestro sets at startup, e.g. MAESTRO_BINARY, not a path baked into the shared shim dir), inherit stdin/stdout/stderr and the environment, and exit with maestro's exit code.
- COMPOSER_DEV_MODE is not the dispatcher's: Installer::run, RunScriptCommand, ScriptAliasCommand, ReinstallCommand and AutoloadGenerator::dump set it, as in Composer. `composer exec` dispatches `__exec_command`; `run-script`/script aliases pass the `script-alias-input` flag.
- Plugin runtime: PHP string listeners become `eventdispatcher.Script`, other callables `PHPCallable`; `removeListener` maps to `MatchCallable`/`MatchObject`/`MatchScript`. A PHP \Error crossing to Go must implement `eventdispatcher.PHPError`; a PHP ScriptExecutionException must be an `*eventdispatcher.ScriptExecutionError` for `errors.As`.

## Users of internal/repository and internal/locker (internal/composer, internal/resolver, internal/installer, internal/command, internal/plugin, composerrepo, vcs)
- Every RepositoryInterface method returns an error where PHP can throw (remote repositories fail anywhere); `RepoName()` cannot and counts the packages loaded so far. String constraints are parsed by the caller (`repository.ParseConstraint`); a nil constraint is PHP's null (any version). `search()`'s `?string $type` is `""` for null; results are `SearchResult` (Abandoned nil = unset), providers `[]ProviderInfo` keyed by name. `Class()` gives the PHP class (plugin mirrors); writable repositories have `Rev()`.
- Subclassing ArrayRepository from another package: not possible (the initialize/addPackage hooks are unexported). composerrepo/vcs repositories implement RepositoryInterface themselves; use `repository.CreateAliasPackage` (ArrayRepository::createAliasPackage), `NewConstraintMap`/`NameMap` (ordered `array<string, X>`), and `LoadResult`/`AlreadyLoaded`.
- `instanceof CompositeRepository` is `repository.AsComposite` (true for InstalledRepository too); other `instanceof` are type assertions on the concrete pointer types. `RepositoryUtils::flattenRepositories` is `FlattenRepositories`.

## Audit: regex errors must surface as Composer does
Several ports treated a regex engine failure (backtrack/recursion limit, bad UTF-8 under /u) as "no match". In PHP it depends on the call: Composer\Pcre\Preg::* throws PcreException (a RuntimeException); bare preg_match/preg_replace/preg_grep return false/null (preg_grep: the entries collected before the error) and the caller decides.

Done (hygiene task) for every package except internal/installer and internal/composer. The engine counts the match limit per start position like PHP's JIT, and many "simple" patterns do fail on subjects of 1 MB or less (`^[a-z0-9]+(\.[a-z0-9]+)*$`, `(.+?)\s*$` already at ~10 KB of whitespace, `.*.*.*.*.*c` built from user globs at ~150 bytes), so "cannot fail" needs a reason, not a feeling.

Rule for internal/installer, internal/composer and later ports:
- Preg::* in PHP: return the `*php.PcreError` up the stack, through whatever PHP lets it pass (check for `catch (\Exception)`/`catch (\RuntimeException)` on the way, e.g. Git::getMirrorDefaultBranch logs and returns null).
- raw preg_*: the error is false/null; do what the PHP caller does with that (`!preg_match` is true, preg_replace's null concatenates as "").
- Ignoring the error (`_`) is allowed only where the pattern provably cannot fail on any input: bounded work per start position (a single character class, an anchored fixed-length prefix, possessive/auto-possessified quantifiers before a disjoint literal) or a subject bounded far below the limit. Say why in a comment at the site.
- Helpers that panic or swallow (`mustMatch`, `matches`, ...) must not wrap patterns that can fail; repository/vcs's `matches`/`match`/`replace` now return errors and `replaceInfallible` is for the provably safe ones.
- New exports for this: `json` detectIndenting is internal (DetectIndenting keeps its signature), `http.FindHeaderValueChecked`/`Response.HeaderChecked`, `repository.SafelyLoadInstalledVersionsChecked` (Factory must use it: a large installed.php can exhaust the limit and Composer lets the exception through), `util.UpdateDistReference` and `util.TryForgejoURL` return errors, `filterlist.FilterListAuditor.GetMatching{Audit,Block}Entries` return errors, `platform.ParseHtmlExtensionInfo` returns an error.
- Known, documented divergence: `util.SanitizeURL` (~100 callers, all building messages) keeps its error-less signature and returns "" where Preg::replaceCallback would throw (a ~1 MB run of [a-z0-9+.-] with an unreachable '@'). Anything that derives more than a message from it (the cache directory names of GitDriver, HgDriver, SvnDriver, ComposerRepository and GitDownloader) uses `util.SanitizeURLChecked`, which returns the error: "" there would name the cache root itself. `util.ComposerMirrorProcessGitURL` reads a failure on a ~1 MB URL as no match.
- Done (#9): internal/pkg's `mustMatch`/`mustReplace` only wrap patterns with bounded work per start position; the sites whose patterns can fail return the error. `platform.ParseOpenssl`/`ParseLibjpeg`/`ParseZoneinfoVersion` return the PcreError.

## Async ordering (internal/util, internal/util/http, internal/downloader, internal/installer)
One scheduling model replaces the goroutine callbacks (internal/util/scheduler.go, promise.go):
- `util.Promise` follows react/promise 3: then() callbacks (`util.Then`, `util.Chain` (a callback may return a promise to follow), `OnSettled`) run synchronously, at once when the promise is settled, else on the goroutine settling it, in the order added. `Wait`/`Err`/`Done` block without driving anything; `Await()` drives the promise's scheduler until it settled. New: `Result()` (non-blocking), `Scheduler()`, `util.Waitable` (any promise), `util.FirstRejection` (all()'s first rejection in time), `util.AwaitAll`.
- `util.Scheduler` is the event loop's run queue: asynchronous work takes a `Ticket` when it starts (on the driving goroutine) and hands its completion to it from its worker goroutine; completions run on the goroutine driving the scheduler, in ticket order. That is the only deliberate difference from Composer's loop, whose completion order is nondeterministic. `util.NewAsync(s, cancel)` (a deferred settled through the scheduler, resolvable from any goroutine), `util.Go(s, fn)` (parallel work), `util.Later(s, fn)` (settle on the next turn: Composer's async work that maestro does at once), `util.NewDeferredOn(s, cancel)` (settled by the driver itself), `Scheduler.Interrupt(fn)` (signal handlers). Only one goroutine may drive a scheduler at a time; nested waits from callbacks are fine.
- Drivers: `Loop.Wait` (until no work is pending, as PHP's; a nil `*Loop` drives the promises' own schedulers), `HttpDownloader.Wait`, `ProcessExecutor.Wait`, `Promise.Await`, `util.AwaitAll`. Never block on `Wait()`/`Err()` of a pending promise inside a callback or on the only goroutine that would drive it: use a nested `Loop.Wait`/`Await`.
- `HttpDownloader.Scheduler()`; `ProcessExecutor.Scheduler()`/`SetScheduler(s)` (`NewLoop` joins the executor to the downloader's). Async HTTP transfers and async processes complete through the scheduler: retries, redirects, auth prompts, "[200] url" debug lines and callbacks run on the driver in start order; queued requests/processes start there after a completion's callbacks (as the next countActiveJobs() tick does).
- Synchronous requests (`Get`/`Copy`) are finished by the waiting goroutine (any goroutine) and do not run other requests' callbacks (Composer's wait($id) ticks every job); they no longer count against `COMPOSER_MAX_PARALLEL_HTTP`, so they never wait for a slot only the driver frees.
- `Cancel()` of a settled promise does nothing (React drops the canceller on settlement).
- internal/downloader: archive extraction into the store during the download phase and materialization from the store are `util.Go` jobs on the ProcessExecutor's scheduler; POST_FILE_DOWNLOAD, the checksum check and cache copies run in the download's callback on the driver, as in Composer.
- internal/installer: `type Promise = util.Promise[struct{}]` (was a struct; `Of`, `Then`, `Resolved`, `Rejected`, `Await`, `Result()` keep their signatures). Tests resolving installer/downloader promises from other goroutines must use `util.NewAsync`/`util.Go` (a plain `NewDeferred` would run the callbacks on that goroutine).

## Exception throw sites (every package; from the error-locations task)
- Mechanism: `internal/phperr` (no dependencies). An error type standing for a PHP exception embeds `phperr.Site`; every construction that can reach the console sets `Site: phperr.At("<basename of the PHP file>", <line of its `new` expression>)` (Composer 2.10.3 or the vendored library: VersionParser.php, JsonParser.php, Filesystem.php of Symfony, ...). A Go helper serving several PHP throw sites takes the site as a parameter. PHP's `$previous` goes in the type's previous field exposed by `PHPPrevious() error` (`phperr.Chained`), never through Unwrap (catch does not look at it); util's RuntimeError, InvalidArgumentError, LogicError and UnexpectedValueError have `Prev`, TransportError's `Previous` is also its PHPPrevious. A PHP class `util.PHPClassOf` does not know is given by a `PHPClass() (string, int)` method (json.ValidationError, jsonlint's exceptions, pkg.TypeError, loader.InvalidPackageError, classmap/spdx/platform/process errors, ...); `php.EngineError` maps to its Class. PHP warnings the ErrorHandler throws (util.ErrorException) take the line of the warning call.
- Rendering: internal/command's `asThrowable` reads `phperr.SiteOf(err)` (the error itself, or a wrapper keeping its message) and `phperr.PreviousOf(err)`; console's renderer falls back to them for non-Throwables. `hintCommonErrors` now also raises the verbosity for `\Error` classes (TypeError, ValueError, ...), as Composer does.
- New ports and new throw sites must set the site; tools/oracle/errors/errors.sh runs Composer and maestro over the scenarios of internal/command/testdata/errors (default/-v/-vv/-vvv, with a local HTTP server) and compares byte for byte; `-w` re-records the goldens TestErrorRendering (internal/command/errorstest, child processes, needs php, skipped with -short) checks. Add a scenario directory (project/, args, optional env and home/) for every new user-facing error path.
- Known remaining differences: "Exception trace:" lists only the throw site (Composer prints its PHP call stack with absolute paths; the oracle drops those frames); TypeErrors of userland PHP functions (pkg.ArgumentTypeError, php.EngineError from typed Composer methods) have no site (PHP reports the callee's declaration line and appends ", called in <path> on line N"); Symfony's own exception subclasses that maestro represents with util's generic types (Finder's DirectoryNotFoundException, Filesystem's IOException/FileNotFoundException, Process exceptions other than timeout/signal) render the generic class name at -v.
- (internal/composer, for internal/plugin) `Factory.createPluginManager` now performs PluginManager::__construct's lock read itself (`readLockForAllowPlugins`: allow-plugins `[]` → `Locker.IsLocked()` and `PluginAPI()`), before calling `CreatePluginManagerFunc`, so the `-vvv` "Reading ./composer.lock" line and a broken lock's exception come at Composer's point for every plugin manager. ## From the hardlink-default task (internal/store, internal/downloader, internal/installer, internal/command)
