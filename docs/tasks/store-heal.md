# Task: store healing without the network, plus e2e/test robustness

1. Store healing. Plugin installers (phpstan/extension-installer, infection/extension-installer, and any tool that edits vendor files in place) modify hardlinked files, so the store detects the change and drops the file; the next project re-downloads the dist and prints a "Downloading" line Composer wouldn't (Composer would print "Loading from cache" because its files cache keeps the archive). Fix so output stays identical to Composer in every such case and nothing is fetched again: keep the dist archive alongside the store exactly where Composer's files cache would (honour cache-files-dir, cache-files-ttl, cache-files-maxsize and the GC rules, so maestro's cache behaves like Composer's), heal tainted store files from the kept archive, and only when the archive is gone fall back to downloading — matching Composer's output for that case too. Re-evaluate the in-place-modification design in internal/store's doc (detection by size+mtime, heal-before-reuse) and make it ironclad: a project must never see another project's in-place edits, under concurrency too. Then remove the MAESTRO_PACKAGE_IMPORT_METHOD=copy workaround from the phpstan/infection plugin fixtures and make sure they pass with the default import method.
2. The e2e `verbosity` scenario fails at random because Composer's cache GC line is printed on a 1-in-51 draw: make the e2e runner neutralise that consistently for both tools (e.g. COMPOSER_TEST_SUITE semantics or the normalisation), as the plugin fixtures do — one mechanism for all scenarios.
3. Flaky `TestInstallationManager_IntegrationZip` (internal/installer): find the root cause and fix it (run -race -count=50).
4. Tests must not fill /tmp: the e2e suites and any test writing large trees must clean up (t.TempDir or explicit cleanup), and the e2e suite should share the downloaded phar/caches sensibly.

Verification: MAESTRO_E2E=1 full TestE2E and TestE2EPlugins pass (cold and warm), all unit tests with -race, lint clean.
Scope: internal/store, internal/downloader, internal/cache, internal/installer (test), cmd/maestro e2e tests/fixtures. A plugin phase-3 agent is concurrently working in internal/plugin and may touch internal/installer's Virtuals seam — coordinate via HANDOFF.md.
